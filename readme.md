# Домашняя работа: обработка сетевых ошибок и завершение потоков

Проект: сетевой чат на PyQt6 (TCP-сокеты, сообщения в формате JSON с 4-байтовым заголовком длины).

## Изменения

Изменялся только `main.py`; `server.py` не менялся.

- `NetCom.close()` идемпотентное закрытие сокета (`shutdown` + `close`), используется и при потере связи, и при закрытии окна.
- `ReceiveThread`:
  - добавлен сигнал `connection_lost(str)`;
  - `run()` перехватывает сетевые ошибки (`OSError`) и ошибки разбора JSON, цикл завершается при `recv() is None`;
  - исключение из рабочего потока не выходит, GUI напрямую не изменяется;
  - добавлен метод `stop()` для штатного завершения без ложного сигнала о потере связи.
- `SendThread`:
  - добавлен метод `stop()`, который кладёт в существующую очередь `None`;
  - `run()` завершает цикл при получении `None`;
  - ошибка отправки (`OSError`) перехватывается и передаётся в GUI сигналом `connection_lost(str)`.
- `MainWindow`:
  - сигналы `connection_lost` обоих потоков подключены к слоту `on_connection_lost()`;
  - при потере связи статус меняется на `Disconnected`, в историю добавляется строка `[Система] Соединение с сервером потеряно`, поля ввода и кнопка Send отключаются, сокет закрывается;
  - повторные сигналы от двух потоков игнорируются, сообщение о потере выводится один раз;
  - `closeEvent()` останавливает оба потока, закрывает сокет и ожидает их завершения (`wait(2000)`), поэтому окно закрывается без зависших потоков.
- Дополнительное задание: индикатор состояния `Connected`/`Disconnected` в `QLabel` (зелёный/красный), обновляется через сигналы и слоты.
